## ViewModel担当

ViewModelは **画面とロジックの接点** のため、以下のルールで作成します：

| ViewModel | 担当 | 理由 |
|-----------|------|------|
| `RadarViewModel` | **久米** | BLEスキャン処理が主要 |
| `MatchListViewModel` | **久米** | DB検索ロジックが主要 |
| `ChatViewModel` | **久米** | リアルタイム通信が主要 |
| `ProfileViewModel` | **久米** | Firebase保存処理が主要 |
| `UserDetailViewModel` | **久米** | ユーザー情報取得が主要 |

**作業フロー：**
1. 久米がViewModelの骨格（State、UIEvent）を作成
2. 昆野がScreenからViewModelを利用してUI接続

## 【重要】コンフリクト回避ルール

### 1. 触らないファイル

| 開発者 | 触らないディレクトリ |
|--------|---------------------|
| **久米** | `ui/screens/`、`ui/theme/`、`ui/components/` |
| **昆野** | `ble/`、`data/`、`di/` |

### 2. 共通ファイルの変更手順

以下のファイルは **必ず相談してから変更** してください：

- `MainActivity.kt`
- `navigation/Screen.kt`
- `navigation/AppNavGraph.kt`
- `domain/model/*.kt`
- `build.gradle.kts`（ルート & app）
- `libs.versions.toml`

**変更手順：**
1. Slackで事前連絡
2. featureブランチで作業
3. Pull Requestでレビュー依頼
4. 承認後にマージ

### 3. ブランチ戦略

```
main (protected)
  ├── develop
  │     ├── feature/kume/ble-manager
  │     ├── feature/kume/user-repository
  │     ├── feature/konno/radar-ui
  │     └── feature/konno/chat-ui
```

**命名規則：**
- `feature/kume/機能名` - 久米の作業
- `feature/konno/機能名` - 昆野の作業

### 4. Syncポイント（統合タイミング）

| Sync | 内容 | 統合作業 |
|------|------|----------|
| **Sync 1** | BLE疎通 | ViewModelとUIの接続 |
| **Sync 2** | DB表示 | リスト表示の統合 |
| **Sync 3** | チャット | リアルタイム通信の統合 |

Syncポイントでは必ず：
1. 両者のブランチを `develop` にマージ
2. 実機2台で動作確認
3. 問題なければ `main` にマージ
